## 2. `nextra-theme-docs@4.6.1` Layout — Zod 4.4.x incompatibility

**Error:** `✖ Invalid input: expected nonoptional, received undefined → at children`

**Root cause:** `nextra-theme-docs`'s `Layout` component destructures `children` out of props before validating the rest against `LayoutPropsSchema`:

```js
// layout.js (compiled output)
({
  children,
  ...themeConfig
} = t0);

const { data, error } = LayoutPropsSchema.safeParse(themeConfig);
//                                             ^ children is MISSING
```

`LayoutPropsSchema` declares `children` as required (`children: reactNode`, not `.optional()`). Up to Zod 4.3.x, a missing key would call the custom validator with `undefined`, and `reactNode`'s checker accepted `undefined` (via `data == null`). Zod 4.4.0 changed this — missing required keys now throw `invalid_type: expected nonoptional` **before** the custom validator runs ([Zod #5661](https://github.com/colinhacks/zod/pull/5661)).

Since `nextra@4.6.1` depends on `zod@^4.1.12` (range allows `4.4.x`), any project with Zod resolved to `>=4.4.0` hits this.

**Fix (local patch):** In `node_modules/nextra-theme-docs/dist/layout.js`, changed:
```js
LayoutPropsSchema.safeParse(themeConfig);
// to:
LayoutPropsSchema.safeParse({ children, ...themeConfig });
```

And destructure `children` from `data` so it doesn't leak into `rest` passed to `ThemeConfigProvider`.

**Upstream:** PR [#4990](https://github.com/shuding/nextra/pull/4990) tracks the fix.

**Workarounds:**
- Pin `zod` to `4.3.x` in `package.json` (add `"zod": "4.3.6"` under `overrides` or `resolutions`)
- Wait for a nextra-theme-docs release incorporating PR #4990
